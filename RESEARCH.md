## 1. The primitive itself (OPENED)

`solana-foundation/subscriptions` was cloned at `299dfea` (2026-09-21) and read directly.

- Three models: fixed delegation, **recurring delegation** (cap resets each period), subscription plan.
- One `SubscriptionAuthority` PDA per `(user, mint)`, approved as the token account's SPL delegate for `u64::MAX`; each pull is checked against a delegation PDA.
- Error `400 = 0x190 AmountExceedsPeriodLimit` (`program/src/errors.rs`).
- **`UNKNOWN_INIT_ID` (`i64::MIN`)** — `CHANGELOG.md` 0.5.0: _"enables one-transaction authority initialization with Subscribe, CreateFixedDelegation, or CreateRecurringDelegation when the new SubscriptionAuthority.init_id matches the current slot."_ Added in commit `55a3efd` (#206).
- The CHANGELOG states the mainnet binary was built at release commit `364a419`. Measured here:

```
$ git merge-base --is-ancestor 55a3efd 364a419 && echo "206 IS in 364a419"
206 IS in 364a419
```

So the one-signature grant path exists in the release the CHANGELOG says is deployed. **The current nuntius app still asks Seed Vault for two signatures** (init, then create). That is the first thing to fix.

- `@solana/subscriptions` on npm: latest `0.5.0`, published 2026-08-10, exports `UNKNOWN_INIT_ID` (read from `server/node_modules/@solana/subscriptions/dist/index.d.ts` line 2340).
- The README lists known limits worth repeating to judges: slot-granular `init_id` rotation, a held durable-nonce init bundle survives revocation, no delinquency state, `MemoTransfer` destinations unsupported.
- Upgrades go through a Squads multisig (SNIPPET: ADR-004 per research agent; the nuntius README records upgrade authority `DXtFpbPjcn2hxPnw79x1Pfoj35vXh5AsWBkS37YnXMVv`, measured 2026-09-22).

## 3. The gap

The standard launched on 2 June 2026 with merchant-side partners only. Every integration found is **merchant-side**: plans, billing, collection. **Nobody gives the user a native place to see, watch and kill these permissions.** Explorer has a read-only web card. No wallet was found with UI for them (Phantom, Solflare, Backpack, Seed Vault — SNIPPET, absence of evidence only).

Meanwhile every authority that is granted is a `u64::MAX` SPL approval on the user's token account. The more merchants adopt the standard, the more of those sit on users' phones with no alarm attached.

## 5. What to steal (from the UX research)

1. A grant sheet that reads as one sentence, with editable amount and period before signing (MetaMask).
2. The payee as a named card with one Revoke button (Coinbase), but native and one signature.
3. A push for every pull showing amount, the cap remaining this period, and the reset time (GoHenry, Privacy.com).
4. A failure or blocked notice that says **why** (Loop, Privacy.com). For us the reason is the program's own error.
5. Morning digest and weekly summary, opt-in, with a user-set hour (Apple Card, but tunable).
